Introduction

ComfyUI를 처음 켜면 노드는 어떻게든 연결하게 됩니다. 막히는 곳은 그다음입니다. models 폴더에는 checkpoint, LoRA, VAE, clip, controlnet 같은 폴더가 줄줄이 있고, Civitai나 Hugging Face에는 이름만 봐서는 뭐가 다른지 모를 모델이 수천 개 있습니다. "Base", "Merge", "Turbo", "Pony", "Illustrious", "Flux" 같은 말도 어디서나 보이지만 설명해 주는 곳은 드뭅니다.
이 글은 모델이 어떻게 학습되는지는 다루지 않습니다. 어떤 파일이 무슨 역할이고, 어떤 상황에 무엇을 골라서, 어디에 넣고 어떻게 쓰는지를 사용자 입장에서 정리합니다.
질문이 글에서 보는 내용
models 폴더의 파일은 각각 뭔가?폴더별 역할과 노드 연결
Checkpoint, Base, Merge는 뭐가 다른가?모델의 "출신" 구분
SD1.5, SDXL, Pony, Flux 중 뭘 쓰나?계열별 특징과 용도

The Big Picture: What Goes Into One Image

이미지 한 장은 여러 모델 파일이 이어서 일을 한 결과입니다. 각 파일이 파이프라인의 어느 단계를 맡는지만 알아도 폴더 이름이 대부분 이해됩니다.
flowchart TB
    A["Text Encoder<br/>(CLIP / T5)"] --> B["Diffusion Model<br/>(UNet / DiT)"]
    L["LoRA"] -.-> B
    L -.-> A
    C["ControlNet"] -.-> B
    B --> D["VAE Decode"]
    D --> E["Upscale Model"]
단계하는 일파일 종류
프롬프트 해석글을 모델이 이해하는 숫자로 바꿉니다Text Encoder (CLIP, T5)
그림 만들기노이즈에서 이미지를 조금씩 만들어 갑니다Diffusion Model (UNet, DiT)
보정화풍, 캐릭터, 구도를 바꿉니다LoRA, ControlNet, Embedding
픽셀로 변환내부 표현을 실제 이미지로 풀어냅니다VAE
후처리해상도를 키우고 디테일을 살립니다Upscale Model, Detailer
핵심은 Diffusion Model이 중심이고, 나머지는 그 모델에 맞춰야 한다는 점입니다. 이 규칙은 뒤에서 계속 나옵니다.

Checkpoint: The All-in-One File

Checkpoint는 가장 흔히 받는 파일입니다. 안에 Diffusion Model, Text Encoder, VAE가 한 파일로 들어 있어서, Load Checkpoint 노드 하나가 MODEL, CLIP, VAE 세 가지 출력을 모두 내줍니다. 처음에는 이 노드 하나에 KSampler와 VAE Decode만 연결하면 이미지가 나옵니다.
Load Checkpoint 출력연결하는 곳
MODELKSampler (LoRA를 쓰면 LoRA를 거쳐서)
CLIPCLIP Text Encode (프롬프트 입력 노드)
VAEVAE Decode

Checkpoint vs split models

SD1.5와 SDXL은 보통 올인원 Checkpoint로 배포됩니다. 반면 Flux, SD3.5, Qwen-Image, Wan 같은 최근 모델은 부품별로 쪼개서 배포하는 경우가 많습니다. 모델이 커서 Text Encoder만 몇 GB이기 때문입니다.
구분올인원 (Checkpoint)분리형 (split)
파일1개Diffusion Model + Text Encoder + VAE
폴더checkpointsdiffusion_models, text_encoders, vae
노드Load CheckpointLoad Diffusion Model + Load CLIP + Load VAE
장점간단하다Text Encoder를 다른 정밀도로 바꾸거나 여러 모델이 공유할 수 있다
예SD1.5, SDXL 계열Flux, SD3.5, Z-Image, Qwen-Image, Wan
분리형은 공식 workflow(예제 JSON)를 먼저 받아서 쓰는 것이 가장 쉽습니다. 노드 연결과 필요한 파일 이름이 이미 정해져 있기 때문입니다. ComfyUI의 Workflow → Browse Templates에 모델별 예제가 들어 있습니다.

Precision (fp32, fp16, bf16, fp8)

정밀도는 숫자 하나를 몇 비트로 저장하느냐입니다. 비트가 적을수록 파일이 작고 VRAM을 덜 쓰지만 품질이 조금 떨어질 수 있습니다.
표기의미특징
fp3232비트가장 크고 거의 쓰지 않습니다
fp16, bf1616비트기본값입니다. 품질 손실이 사실상 없습니다
fp8 (e4m3fn, e5m2)8비트크기가 절반입니다. 눈으로 구분이 어려운 경우가 많습니다
Q8, Q5, Q4 (GGUF)양자화숫자가 작을수록 작고 품질이 조금씩 떨어집니다
체크포인트 이름의 pruned, ema도 자주 보입니다. 학습할 때만 필요한 가중치를 덜어낸 파일이 pruned이고, 생성만 하는 사용자는 이쪽을 받으면 됩니다. 대략 SD1.5 fp16은 2GB, SDXL fp16은 6~7GB 정도입니다.

Base, Fine-tune, Merge: Where a Model Comes From

Civitai의 체크포인트는 "어떻게 만들어졌는지"로 크게 세 종류가 있습니다. 이 구분을 알면 모델 설명을 읽을 때 훨씬 편합니다.
종류만든 방식특징예
Base (원본)회사가 처음부터 대규모로 학습범용입니다. 특정 화풍이 없어서 다른 모델의 뿌리가 됩니다SD1.5, SDXL 1.0, Flux.1 dev
Fine-tuneBase에 추가 데이터를 학습한 방향(애니, 실사, 특정 소재)에 특화됩니다Pony Diffusion, Illustrious XL
Merge여러 모델의 가중치를 비율로 섞음학습 없이 섞어서 취향 맞는 결과를 만듭니다Civitai의 인기 모델 대부분

Merge는 나쁜 것인가

아닙니다. 다만 성격을 알아야 합니다.
  • 장점: 여러 모델의 장점을 섞어서 결과가 바로 예쁘게 나옵니다.
  • 단점: 어떤 모델이 얼마나 섞였는지 불투명하고, 프롬프트 반응이 모델마다 다릅니다. 라이선스도 섞입니다.
  • 팁: 초보에게는 인기 많은 merge가 오히려 쉽습니다. 고급 사용자는 Base나 Fine-tune에 LoRA를 얹어서 직접 조절합니다.

Distilled: Turbo, Lightning, Hyper, schnell

"몇 단계 만에 그리게 줄인" 모델들입니다. 원래 2030 steps가 필요한 모델을 18 steps로 줄였습니다.
이름보통 stepsCFG비고
SDXL Turbo, SD Turbo1~41 전후속도 위주, 해상도 낮음
SDXL-Lightning, Hyper-SD2~81~2LoRA로도 배포되어 아무 SDXL 모델에 얹을 수 있습니다
LCM4~81~2LoRA를 얹는 방식, 설정이 까다롭습니다
Flux.1 schnell1~41라이선스가 자유롭습니다 (Apache 2.0)
빠르게 구도를 훑어볼 때는 좋지만, 디테일과 프롬프트 충실도는 일반 모델이 보통 더 낫습니다. 구도를 Turbo로 잡고 마지막만 일반 모델로 올리는 식으로 나눠 쓰기도 합니다.

계열별 사용 팁

  • SD1.5: 구형이라 해상도를 512 근처로 두고, 크게 뽑으려면 업스케일로 올립니다. 애니 계열은 Clip skip 2를 요구하는 경우가 많습니다.
  • SDXL: 1024x1024 근처(1216x832, 832x1216 등 비슷한 면적)로 뽑습니다. 해상도가 크게 벗어나면 구도가 깨집니다.
  • Pony: 품질 태그(score_9, score_8_up, score_7_up 등)를 앞에 붙이는 방식이 필요합니다.
  • Illustrious / NoobAI: Danbooru 태그 위주로 씁니다. 모델 카드가 추천하는 품질 태그를 따르세요.
  • Z-Image Turbo: 분리형이라 Diffusion Model, Text Encoder(Qwen 계열 LLM), VAE를 따로 받습니다. steps는 8 전후, CFG는 1 전후로 두고 문장으로 설명합니다. 공식 템플릿 workflow가 가장 쉽습니다.
  • Flux: 문장으로 설명합니다. CFG는 1로 두고 FluxGuidance 노드로 강도(3.5 전후)를 조절합니다. dev는 negative prompt가 사실상 듣지 않습니다.
모델마다 권장 설정이 다르니, 모델 상세 페이지의 Sampler, Steps, CFG, Clip skip 안내를 먼저 따라 하는 것이 가장 빠릅니다.

LoRA: Small Add-on Files

LoRA는 Checkpoint 위에 얹는 작은 보정 파일입니다. 용량이 수십~수백 MB라서 모델 전체를 받지 않고도 특정 캐릭터, 화풍, 옷, 포즈를 추가할 수 있습니다.
LoRA 종류용도예
Character특정 인물, 캐릭터얼굴과 의상 유지
Style화풍, 색감수채화, 특정 작가풍
Concept특정 소재, 사물, 포즈특정 옷, 배경
Detail / Slider디테일, 나이, 표정 같은 한 축의 조절슬라이더 LoRA
Speed적은 steps로 그리게 함Lightning, Hyper, LCM

How to use it in ComfyUI

  1. 파일을 models/loras에 넣고 새로고침합니다.
  2. Load LoRA 노드를 Load Checkpoint 뒤에 연결합니다. MODEL과 CLIP을 받아서 다시 MODEL과 CLIP을 내보냅니다.
  3. 나온 MODEL은 KSampler로, CLIP은 CLIP Text Encode로 연결합니다.
  4. 여러 개를 쓰려면 Load LoRA 노드를 이어서 붙입니다.
노드 입력의미처음 값
strength_model그림 생성 모델에 주는 영향0.6 ~ 1.0
strength_clip글 해석에 주는 영향strength_model과 같게, 문제가 있으면 낮춤
Flux나 영상 모델처럼 Text Encoder를 건드리지 않는 경우는 LoraLoaderModelOnly 노드를 씁니다.

LoRA를 쓸 때 꼭 알아야 할 것

  • 계열이 맞아야 합니다. SD1.5용 LoRA는 SDXL에 못 씁니다. Flux용은 Flux에만 됩니다.
  • 트리거 단어를 확인하세요. 많은 LoRA가 프롬프트에 특정 단어를 써야 작동합니다. 모델 페이지에 적혀 있습니다.
  • 강도는 낮게 시작하세요. 1.0에서 얼굴이 뭉개지거나 색이 탁해지면 0.6~0.8로 낮춥니다.
  • 여러 개를 겹치면 서로 싸웁니다. 합이 1.5~2를 넘으면 결과가 깨지기 쉽습니다.
  • 같은 SDXL이라도 Pony용 LoRA를 Illustrious에, 또는 반대로 쓰면 잘 안 맞는 경우가 많습니다. 학습한 모델 계열을 확인하세요.

VAE, Text Encoder, Embedding

VAE

VAE는 모델 내부의 압축된 표현(latent)을 실제 픽셀 이미지로 바꿔 주는 부품입니다. 대부분의 Checkpoint는 VAE가 들어 있어서 따로 받을 필요가 없습니다. 증상이 있을 때만 별도 VAE를 연결합니다.
증상원인과 해결
색이 탁하고 회색빛이다내장 VAE가 약한 모델입니다. 모델이 권장하는 VAE를 Load VAE로 연결합니다
SDXL에서 검은 이미지fp16 NaN 문제입니다. sdxl-vae-fp16-fix 같은 수정 VAE를 사용합니다
Flux/SD3에서 색이 이상하다Flux는 전용 ae.safetensors를 써야 합니다. SD1.5, SDXL의 VAE와 호환되지 않습니다

Text Encoder (CLIP, T5)

프롬프트를 모델이 이해하는 숫자로 바꿉니다. 계열마다 쓰는 조합이 다릅니다.
계열Text Encoder
SD1.5CLIP-L
SDXLCLIP-L + CLIP-G
Flux, SD3.5CLIP-L + T5-XXL (긴 문장 이해)
Z-Image, Qwen-ImageQwen 계열 LLM (한글 등 다국어 이해)
T5-XXL은 fp16 기준 약 9~10GB로 커서, 메모리가 부족하면 fp8 버전을 쓰기도 합니다. SD1.5 계열 애니 모델은 CLIP Set Last Layer 노드를 -2로 두면 Clip skip 2와 같습니다.

Embedding (Textual Inversion)

아주 작은 파일(수십 KB)로, 특정 개념을 하나의 단어처럼 만들어 줍니다. models/embeddings에 넣고 프롬프트에 embedding:파일이름으로 부릅니다. 예전에는 EasyNegative 같은 negative embedding이 흔했지만, 지금은 LoRA와 최신 모델에 밀려 쓰임이 줄었습니다.

ControlNet, IP-Adapter and Upscalers

ControlNet: Control the Composition

ControlNet은 참고 이미지에서 윤곽선, 깊이, 포즈 같은 정보를 뽑아서 그림의 구도를 고정하는 모델입니다. 전처리(Preprocessor) 노드는 comfyui_controlnet_aux 커스텀 노드에 들어 있습니다.
종류입력으로 쓰는 정보이럴 때
Canny외곽선사진의 형태를 그대로 두고 화풍만 바꿀 때
Depth거리 정보공간감과 원근을 유지할 때
OpenPose사람 뼈대포즈를 지정할 때
Lineart / Scribble선화, 낙서스케치를 완성작으로 만들 때
Tile원본 질감업스케일하며 디테일을 살릴 때
ControlNet도 계열이 맞아야 합니다. SD1.5용을 SDXL에 쓸 수 없고, Flux는 전용 ControlNet 또는 Union 모델을 씁니다.

IP-Adapter and Redux: Image as a Prompt

글 대신 참고 이미지로 스타일이나 인물의 느낌을 가져옵니다. IP-Adapter는 커스텀 노드(ComfyUI_IPAdapter_plus)와 clip_vision 모델이 필요하고, Flux는 Redux가 비슷한 역할을 합니다. LoRA를 학습하기 부담스러울 때 좋은 대안입니다.

Upscale Models

Load Upscale Model → Upscale Image (using Model)로 쓰는 ESRGAN 계열 모델입니다. 학습 없이 빠르게 해상도를 2~4배로 키웁니다. 애니는 애니용, 사진은 사진용을 고르는 식으로 화풍에 맞춰 선택합니다.
방식설명특징
Upscale Model이미지 자체를 확대빠르고 결과가 안정적입니다
Latent Upscale + 재샘플링latent를 키운 뒤 다시 그림디테일이 새로 생기지만 denoise가 높으면 모양이 변합니다
두 방식을 조합모델로 키운 뒤 낮은 denoise(0.2~0.4)로 한 번 더가장 많이 쓰는 방식입니다

Detailer (Impact Pack)

얼굴이 작게 나와 뭉개질 때, 얼굴 영역만 검출해서 그 부분만 크게 다시 그리는 방식입니다. 검출 모델은 ultralytics/bbox에 두고, 영역 분할 모델은 sams에 둡니다. ComfyUI Manager에서 Impact Pack을 설치하면 함께 받을 수 있습니다.

Compatibility Rules: Mix Only What Matches

오류가 나거나 결과가 이상하면 대부분 "계열이 안 맞는" 경우입니다.
조합되나?비고
SDXL Checkpoint + SDXL LoRAO이상적
SDXL Checkpoint + SD1.5 LoRAX에러나 의미 없는 결과
Pony Checkpoint + Illustrious LoRA대체로 어색둘 다 SDXL 기반이지만 학습 방식이 달라 호환이 낮습니다
SD1.5 Checkpoint + SDXL ControlNetX계열 일치 필요
Flux + SDXL VAEXFlux는 전용 VAE
SDXL Checkpoint + 다른 SDXL VAEO색 문제가 있을 때 교체
에러 메시지로도 짐작할 수 있습니다. mat1 and mat2 shapes cannot be multiplied, size mismatch 같은 메시지는 거의 항상 서로 다른 계열의 모델을 연결했다는 뜻입니다.

VRAM Guide

ComfyUI는 모델을 필요할 때만 올리고 내리는 식으로 메모리를 아끼기 때문에, 부족해도 느리게나마 도는 경우가 많습니다. 그래도 목표를 정할 때는 아래가 기준이 됩니다.
VRAM편하게 쓸 수 있는 것부족할 때 방법
6~8GBSD1.5, SDXL (fp16)해상도를 낮추고 tiled VAE를 사용
12GBSDXL 전반, Flux fp8, Z-Image TurboFlux GGUF Q5 정도
16GBFlux dev fp8, SD3.5 Large영상 모델은 짧은 길이로
24GB~Flux fp16, Qwen-Image, 영상 모델
부족하면 ① 같은 모델의 fp8·GGUF 버전, ② T5 같은 Text Encoder를 fp8 버전으로, ③ --lowvram 옵션 순으로 시도합니다. 메모리가 부족해서 OOM(Out Of Memory)이 나는 경우에는 해상도를 낮추는 것이 가장 빠른 해결입니다.
