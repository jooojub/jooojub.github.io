Introduction

When you launch ComfyUI for the first time, connecting nodes is usually manageable. The real confusion starts right after. Inside the models directory, you find a long list of subfolders like checkpoint, LoRA, VAE, clip, and controlnet. On Civitai or Hugging Face, thousands of models are listed, and their names alone rarely make their differences clear. Terms like "Base," "Merge," "Turbo," "Pony," "Illustrious," and "Flux" appear everywhere, yet few places explain what they actually mean.
This article does not cover how models are trained. Instead, it explains from a user's practical perspective what role each file serves, how to choose the right one for your scenario, where to place it, and how to use it.

The Big Picture: What Goes Into One Image

A single generated image is the result of multiple model files working in sequence. Understanding which stage of the pipeline each file handles clarifies almost every folder name.
flowchart TB
    A["Text Encoder<br/>(CLIP / T5)"] --> B["Diffusion Model<br/>(UNet / DiT)"]
    L["LoRA"] -.-> B
    L -.-> A
    C["ControlNet"] -.-> B
    B --> D["VAE Decode"]
    D --> E["Upscale Model"]
StageWhat It DoesFile Type
Prompt InterpretationTranslates text into numbers the model understandsText Encoder (CLIP, T5)
Image GenerationProgressively shapes an image out of noiseDiffusion Model (UNet, DiT)
AdjustmentModifies art style, character, or compositionLoRA, ControlNet, Embedding
Pixel ConversionDecodes the internal latent representation into real pixelsVAE
Post-processingUpscales resolution and refines detailsUpscale Model, Detailer
The core rule is that the Diffusion Model is the center, and everything else must match that model. This rule will come up repeatedly throughout this guide.

If you already use Automatic1111 or another UI, you do not need to duplicate your model files. You don't have to keep duplicate copies of multi-gigabyte models.

Checkpoint: The All-in-One File

A Checkpoint is the most common file type you will download. Because it bundles the Diffusion Model, Text Encoder, and VAE into a single file, a single Load Checkpoint node outputs all three: MODEL, CLIP, and VAE. Initially, connecting just this node to a KSampler and VAE Decode is enough to produce an image.
Load Checkpoint OutputWhere to Connect
MODELKSampler (or through a LoRA if using one)
CLIPCLIP Text Encode (prompt input node)
VAEVAE Decode

Checkpoint vs split models

SD1.5 and SDXL are commonly distributed as all-in-one Checkpoints. In contrast, modern models such as Flux, SD3.5, Qwen-Image, and Wan are frequently distributed in modular components. Because these models are so large, the Text Encoder alone can take up several gigabytes.
CategoryAll-in-One (Checkpoint)Modular (Split)
Files1 fileDiffusion Model + Text Encoder + VAE
Foldercheckpointsdiffusion_models, text_encoders, vae
NodesLoad CheckpointLoad Diffusion Model + Load CLIP + Load VAE
AdvantagesSimple to set upAllows swapping Text Encoders to different precisions or sharing across models
ExamplesSD1.5, SDXL familiesFlux, SD3.5, Z-Image, Qwen-Image, Wan
For modular models, loading an official workflow (example JSON) first is the easiest route. The node wiring and expected filenames are already configured for you. Model-specific templates can be found under Workflow → Browse Templates inside ComfyUI.

File Formats and Precision

Even for the exact same model, suffixes appended to the filename indicate significant differences in size and security.

Extension

ExtensionDescriptionRecommendation
.safetensorsSafe format containing raw numbers (tensors) onlyAlways download this
.ckptBased on Python pickle; can execute arbitrary code when loadedAvoid whenever possible
.ggufFormat for quantized large models (requires ComfyUI-GGUF custom node)When VRAM is limited
.pt, .pth, .binLegacy formats; still found in some upscalersOnly from trusted sources

Precision (fp32, fp16, bf16, fp8)

Precision refers to how many bits are used to store each numeric value. Fewer bits result in smaller file sizes and lower VRAM usage, though a subtle loss in quality may occur.
NotationMeaningCharacteristics
fp3232-bitLargest file size; rarely used
fp16, bf1616-bitStandard default; practically zero quality loss
fp8 (e4m3fn, e5m2)8-bitHalf the size; differences are often imperceptible to the eye
Q8, Q5, Q4 (GGUF)QuantizedSmaller numbers use less memory with slight, progressive quality degradation
You will also frequently encounter labels like pruned and ema in checkpoint names. A pruned file strips out training-only weights; users generating images should download this version. As a general rule of thumb, an SD1.5 fp16 model is around 2GB, while an SDXL fp16 model is around 6–7GB.

Base, Fine-tune, Merge: Where a Model Comes From

Checkpoints on Civitai fall broadly into three categories based on "how they were created." Knowing this distinction makes reading model descriptions much easier.
TypeHow It Was MadeCharacteristicsExamples
Base (Original)Trained from scratch by an organization on large datasetsGeneral-purpose; lacks specific style biases, acting as the foundation for other modelsSD1.5, SDXL 1.0, Flux.1 dev
Fine-tuneBase model trained on additional curated dataSpecialized toward a specific domain (anime, realism, specific subjects)Pony Diffusion, Illustrious XL
MergeWeighted combination of multiple modelsBlended without training to achieve appealing, customized aestheticsMost popular models on Civitai

Are Merges Bad?

Not at all. You simply need to understand their trade-offs.
  • Pros: They combine the strengths of multiple models, producing appealing results right out of the box.
  • Cons: It is often unclear which models were blended in what ratios, and prompt adherence varies between checkpoints. Licenses also become mixed.
  • Tip: For beginners, highly rated merges are often the easiest to use. Advanced users often prefer taking a Base or Fine-tune model and layering LoRAs for precise control.

Distilled: Turbo, Lightning, Hyper, schnell

These are models distilled to generate images in significantly fewer steps. They reduce generations that originally required 20–30 steps down to 1–8 steps.
NameTypical StepsCFGNotes
SDXL Turbo, SD Turbo1–4Around 1Focused on speed; lower base resolution
SDXL-Lightning, Hyper-SD2–81–2Also distributed as LoRAs that can be applied to any SDXL model
LCM4–81–2LoRA-based acceleration; more sensitive to settings
Flux.1 schnell1–41Permissive license (Apache 2.0)
While excellent for rapid composition sketching, standard models usually offer better fine detail and prompt fidelity. A common workflow is sketching compositions with a Turbo model, then switching to a standard model for the final render.

Other labels you will see

LabelMeaning
InpaintingModels specialized for repainting selected image regions. Many standard models handle inpainting well today, making dedicated models optional
RefinerAuxiliary models designed to polish late-stage SDXL steps. Rarely used today
Edit / KontextInstruction-based editing models where you provide an image and instruct "modify it like this"
NSFW / SFWThe bias of the training data. Check the model page guidelines and licensing

Practical Tips by Family

  • SD1.5: Being an older architecture, keep resolution around 512px and upscale afterward for high-res outputs. Anime checkpoints frequently require Clip skip 2.
  • SDXL: Generate around 1024x1024 (or equivalent surface areas like 1216x832, 832x1216). Straying too far from native resolution causes composition issues.
  • Pony: Requires prepending quality tags (such as score_9, score_8_up, score_7_up).
  • Illustrious / NoobAI: Primarily driven by Danbooru tags. Follow the quality tags recommended on the model card.
  • Z-Image Turbo: Being modular, you download the Diffusion Model, Text Encoder (Qwen-series LLM), and VAE separately. Set steps to ~8, CFG around 1, and prompt using descriptive sentences. Using the official template workflow is easiest.
  • Flux: Prompt using natural language sentences. Keep CFG at 1 and adjust guidance scale (~3.5) with the FluxGuidance node. Note that negative prompts are practically ignored by Flux dev.
Because recommended parameters vary by model, following the Sampler, Steps, CFG, and Clip skip recommendations on the model details page is always the fastest path to good results.

LoRA: Small Add-on Files

A LoRA is a compact modifier file applied on top of a Checkpoint. Weighing only tens to hundreds of megabytes, it lets you introduce specific characters, artistic styles, clothing, or poses without having to download an entirely new base model.
LoRA TypePurposeExample
CharacterSpecific individuals or charactersPreserving facial features and outfits
StyleArt styles and palettesWatercolor, specific artist styles
ConceptSpecific objects, props, posesSpecialized clothing, backgrounds
Detail / SliderSingle-axis adjustments like detail, age, or expressionSlider LoRAs
SpeedEnables generation with fewer stepsLightning, Hyper, LCM

How to use it in ComfyUI

  1. Place the file in models/loras and refresh.
  2. Wire the Load LoRA node downstream of the Load Checkpoint node. It accepts MODEL and CLIP inputs and outputs modified MODEL and CLIP signals.
  3. Pass the resulting MODEL to KSampler, and CLIP to CLIP Text Encode.
  4. To apply multiple LoRAs, chain Load LoRA nodes sequentially.
Node InputMeaningStarting Value
strength_modelInfluence on image generation model0.6 – 1.0
strength_clipInfluence on text interpretationSame as strength_model, or lower if issues occur
For architectures that do not modify the Text Encoder, such as Flux or video models, use the LoraLoaderModelOnly node instead.

Essential Rules When Using LoRAs

  • Lineages must match. An SD1.5 LoRA cannot be used on SDXL. A Flux LoRA only works on Flux.
  • Check trigger words. Many LoRAs require specific trigger keywords in the prompt to activate. These are listed on the model page.
  • Start with lower strength. If faces look distorted or colors appear oversaturated/burned at 1.0, lower it to 0.6–0.8.
  • Stacking too many causes interference. If total cumulative strength exceeds 1.5–2.0, the image is prone to breaking down.
  • Even within SDXL, using a Pony LoRA on Illustrious (or vice versa) often results in poor compatibility. Always check which base architecture the LoRA was trained on.

VAE, Text Encoder, Embedding

VAE

The VAE converts compressed latent representations from the model into actual pixel images. Most Checkpoints bundle a built-in VAE, so downloading a separate one is usually unnecessary. Connect an external VAE only when troubleshooting specific visual flaws.
SymptomCause & Solution
Colors look dull and washed outThe embedded VAE is weak. Connect the model's recommended VAE using Load VAE
Pure black images on SDXLfp16 NaN overflow issue. Use a patched VAE such as sdxl-vae-fp16-fix
Strange colors on Flux/SD3Flux requires its dedicated ae.safetensors. It is incompatible with SD1.5 or SDXL VAEs

Text Encoder (CLIP, T5)

Translates prompt text into numerical vectors that the model understands. Different families use different combinations.
FamilyText Encoder
SD1.5CLIP-L
SDXLCLIP-L + CLIP-G
Flux, SD3.5CLIP-L + T5-XXL (for long sentence comprehension)
Z-Image, Qwen-ImageQwen-family LLMs (for multilingual comprehension, including Korean)
T5-XXL is large—around 9–10GB in fp16—so fp8 variants are commonly used when memory is tight. For SD1.5 anime models, setting a CLIP Set Last Layer node to -2 is equivalent to Clip skip 2.

Embedding (Textual Inversion)

Very small files (tens of KB) that package a specific concept into a single keyword. Place them in models/embeddings and invoke them in your prompt using embedding:filename. Negative embeddings like EasyNegative were once common, but their usage has declined with modern models and LoRAs.

ControlNet, IP-Adapter and Upscalers

ControlNet: Control the Composition

ControlNet extracts structural guides—such as outlines, depth maps, or poses—from a reference image to lock down the composition. Preprocessor nodes are available via the comfyui_controlnet_aux custom node pack.
TypeInput Feature UsedBest Used For
CannyEdge outlinesPreserving precise silhouettes while changing art style
DepthDepth / distance dataMaintaining spatial depth and perspective
OpenPoseHuman skeletal keypointsExplicitly directing human poses
Lineart / ScribbleLine drawings, rough sketchesTurning concept sketches into finished art
TileOriginal image texturesPreserving textures while upscaling and adding detail
ControlNet models must also match the base family. SD1.5 ControlNets cannot be used with SDXL, and Flux uses dedicated ControlNet or Union models.

IP-Adapter and Redux: Image as a Prompt

Transfers styles or subject likeness using reference images instead of text prompts. IP-Adapter requires a custom node (ComfyUI_IPAdapter_plus) and a clip_vision model; Redux serves an equivalent role in the Flux ecosystem. It is an excellent alternative when training a custom LoRA is impractical.

Upscale Models

These are ESRGAN-based models used via Load Upscale Model → Upscale Image (using Model). They scale resolution 2x to 4x instantly without additional training. Pick a model tailored to your style: anime upscalers for anime art, and photo upscalers for photography.
MethodDescriptionCharacteristics
Upscale ModelDirectly scales the pixel imageFast and highly consistent
Latent Upscale + ResamplingEnlarges the latent and regeneratesIntroduces new fine details, but high denoise values can alter shapes
Hybrid ApproachScale with model first, then refine with low denoise (0.2–0.4)The most widely used approach

Detailer (Impact Pack)

When faces render small in the frame and lose detail, this technique detects the face region and repaints just that segment at higher resolution. Place detection models in ultralytics/bbox and segmentation models in sams. Installing Impact Pack via ComfyUI Manager downloads the required components.

Compatibility Rules: Mix Only What Matches

Whenever an error occurs or the image looks broken, mismatched model families are almost always the cause.
CombinationWorks?Notes
SDXL Checkpoint + SDXL LoRAYesIdeal pairing
SDXL Checkpoint + SD1.5 LoRANoProduces errors or gibberish output
Pony Checkpoint + Illustrious LoRAMostly awkwardBoth originate from SDXL, but different tuning approaches cause poor compatibility
SD1.5 Checkpoint + SDXL ControlNetNoArchitectures must match
Flux + SDXL VAENoFlux requires its dedicated VAE
SDXL Checkpoint + Different SDXL VAEYesUseful to fix color or NaN issues
Error logs often tell the story. Messages like mat1 and mat2 shapes cannot be multiplied or size mismatch almost always indicate that models from different families were wired together.

VRAM Guide

Because ComfyUI aggressively conserves memory by loading and unloading models on demand, workflows can often complete even when memory is tight, albeit more slowly. The following can serve as a baseline when planning your setup.
VRAMComfortable UsageFallbacks When Memory Is Tight
6–8GBSD1.5, SDXL (fp16)Lower resolution; use tiled VAE
12GBGeneral SDXL, Flux fp8, Z-Image TurboFlux GGUF Q5
16GBFlux dev fp8, SD3.5 LargeShorter frame counts for video models
24GB+Flux fp16, Qwen-Image, Video models
When memory runs short, try: ① fp8 or GGUF variants of the model, ② an fp8 version of heavy Text Encoders like T5, and ③ the --lowvram launch flag. If an Out Of Memory (OOM) error occurs, lowering the generation resolution is the fastest fix.

Pre-download checklist:
  • Confirm the file extension is .safetensors.
  • Verify that the Base Model matches your target workflow family.
  • Select the precision (fp16, fp8, pruned) that matches your VRAM capacity.
  • Check the license and source. Avoid unfamiliar .ckpt files or archives bundled with .exe files.
