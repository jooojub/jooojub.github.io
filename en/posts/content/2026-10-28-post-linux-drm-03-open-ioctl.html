In Part 2, we looked at the process of creating nodes such as /dev/dri/card0. This post traces the kernel functions executed the moment a user uses that node—specifically through open() and ioctl(). Finally, we will look at an example performing the same tasks in user space using libdrm.

Code Flow 3: open()

When a user calls open("/dev/dri/card0"), the kernel looks up the stub fops previously registered with major number 226. The stub does not perform real work itself; instead, it swaps out the file operations table with the driver's own.

drm_file_alloc() allocates the state corresponding to a single open(). The object_idr mentioned earlier, the event queue, and other fields are initialized here.
drivers/gpu/drm/drm_file.c - drm_file_alloc() (L132-197)
c
Source drivers/gpu/drm/drm_file.c L132-L197 (Linux v6.19)
drm_gem_open() initializes the handle table, which internally calls idr_init_base(&file_private->object_idr, 1). This is the reason why handle numbers start from 1 (leaving 0 to represent "none"). Thanks to filp->private_data = priv, subsequent ioctl, read, and mmap calls can directly obtain drm_file from file->private_data.

Code Flow 4: ioctl()

ioctl(fd, DRM_IOCTL_xxx, arg) enters into drm_ioctl(), which serves as fops->unlocked_ioctl.

c
Source drivers/gpu/drm/drm_ioctl.c L821-L919 (Linux v6.19)
Summarizing the core steps:
  1. Checks whether the type of the ioctl number is 'd' (DRM_IOCTL_BASE).
  2. If the number is 0x40 or greater, it looks up the entry in the driver table (dev->driver->ioctls); otherwise, it looks in the core table (drm_ioctls[]).
  3. Rather than trusting the size provided by the user, it calculates the buffer size using the kernel definition (ioctl->cmd) (Do not trust userspace).
  4. After copy_from_user(), drm_ioctl_kernel() checks permissions and invokes the actual function.

Summary

Here is what we covered in this post:
  • open: The stub replaces the fops with the driver's own, and drm_file_alloc() creates the state (handle table, event queue) for a single open().
  • ioctl: drm_ioctl() locates the entry in the core or driver table, and drm_ioctl_permit() validates permissions before calling the handler.
  • Most libdrm functions are thin wrappers around these ioctl calls.
